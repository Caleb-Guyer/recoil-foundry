# Upgrade compatibility and branching roadmap

**Status: audited proposal, not implemented gameplay.** Baseline: game **2.70.0**, commit `06a0526`, 13 September 2026. The existing Ray fix remains intact. New names and tuning values below are proposals.

The goal is one gun with a recognizable identity, several meaningful directions per build, and no upgrade whose main effect silently disappears after another pick. Keep Precision, Bullet hell and Demolition. Add **local forks** inside them and inside shared upgrade families; do not add another global path yet.

## What the audit establishes

There are **67 upgrades** and **2,211 unordered pairs**. Expanding both upgrades' prerequisites produces **2,003 allowed pairs** and **208 blocked pairs**. Every upgrade has a reachable prerequisite chain. For every pair, eligibility agrees in both dependency-respecting acquisition orders; allowed pairs also produce the same base gun stats within floating-point tolerance.

The complete [compatibility inventory](upgrade-compatibility.csv) records both build orders and each blocker, including inherited prerequisites. Regenerate it with:

```sh
node --experimental-strip-types scripts/audit-upgrades.mjs
```

These checks establish **eligibility and base stats**, not whether all combat effects combine correctly or whether a build is balanced. The runtime review below follows the conversion, collision, secondary-effect and charge systems. The 306 existing tests in the relevant upgrade, path, Daily and Workshop suites also pass. Higher-order interactions and new designs still need the targeted scenarios listed below.

Keep the existing broad-path exclusions. Cutting Torch remains an alternative to Recall, Vector, Grindshot, Rail spike and Mass Driver; their dependent upgrades inherit that restriction. Mass Driver remains an alternative to Rail spike. These are real weapon-form differences, rather than upgrades offered without a working effect.

## New branches: twelve upgrades

These are **small local choices**, not twelve new starting upgrades. Keep broad path labels concise. A specialization card may add a short label such as “Beam · Charge”; hide incompatible future offers instead of covering cards with lock lists. Discovery screens must still hide unseen upgrades and encounters.

All numerical values in this section are initial tuning targets, not verified balance. Specializations that replace a behavior must keep the existing upgrade's benefit through an explicit adaptation or a clearly declared alternative.

### Precision: three beam specializations

```text
Cutting Torch
  ├─ Pulse Chamber    [requires Burst fire]  — rhythm and a piercing finisher
  ├─ Charge Lens                            — hold, release, reposition
  └─ Prism Array                            — split aim across two lanes

Choose one specialization.
Burst fire and Thermal Runaway remain compatible base modifiers.
```

## One interaction model for every weapon

Do not grow another collection of scattered `if (!rail)` exceptions. Keep upgrade eligibility and runtime capability separate:

1. **Upgrade definition:** existing ID, broad path, prerequisites, optional local choice group, discovery status, and minimum reward stage.
2. **Weapon behavior:** projectile, continuous beam or charged beam; cadence; geometry; flight controller; terminal impact; secondary effects. Conversion adapters resolve what each owned modifier means.
3. **Explicit compatibility result:** `native`, `adapted`, `conditional`, or `blocked`, with the contextual card description produced by the same definition. A conditional modifier still needs an achievable payoff during normal play.
4. **Shot lineage:** record a root discharge, source type, payload snapshot and consumed effect budgets. Splitting, portals, echoes, return legs and Orbit cannot turn an old shot into a fresh paid discharge.

Proposed local choice groups:

| Group                | Members                                   |
| -------------------- | ----------------------------------------- |
| Beam specialization  | Pulse Chamber / Charge Lens / Prism Array |
| Crossfire pattern    | Convergence / Pinwheel                    |
| Echo placement       | Parallax / Follow-through                 |
| Shell specialization | Implosion / Shaped Charge / Cluster Shell |
| Ball behavior        | Drop Forge / Skid Plate                   |
| Portal use           | Rewire / Relay Gate                       |
| Arc discharge        | Daisy Chain / Short Circuit               |
| Ram finish           | Wrecking Ball / Triphammer                |
| Saw travel           | Corner Cutter / Crosscut                  |

A local choice occupies only its own group. Shared upgrades remain available. Keep the current one-fusion rule; Implosion remains a fusion, while the new shell options are ordinary specializations with their own group exclusion. Do not allow an alternative choice to sneak in through its child or a preset.

### Damage and effect rules

- **More geometry does not multiply the entire gun for free.** Divide a declared payload across pellets, rays, echo children, saws or bomblets. Count recoil at the intended discharge, not per child.
- **Primary hits may start secondary effects. Secondary damage cannot recursively start the whole gun again.** Explicit exceptions are the finite Death bloom, linked-charge and Flashpoint rules, each with its own source eligibility and budget.
- **Beam contacts use pulse time, never frame rate.** Front, rear, prism and bank segments share charge and proc ownership. Physical damage must match the visible firing window.
- **Return is a phase, not a new projectile purchase.** A declared return hit allowance may refresh once. Banks, teleports and Orbit do not reset it repeatedly.
- **On-kill healing is credited once per actual enemy death**, regardless of direct shot, burn, saw, blast or physical impact. Reflected shots keep their existing cap.
- **Preserve force and density bounds.** Current limits include 180 shots, 48 Mass Driver balls, eight saws, two wires and 24 stored Orbit rounds. New branches share these limits. Define how excess secondary payload is combined or rejected before tuning dense builds.

## Offers, saves and rollout

**Offers:** retain the 1.5× preference for the chosen broad path. Start new specialized cards at stage 7, with their prerequisites required. Avoid flooding early picks with deep children. Test pool exhaustion after each local fork. Standard rewards, detours, boss salvage, Overtime, test presets and Workshop must call the same eligibility logic. Salvage insertion currently has a separate path in `rewardMods`; bring it under the same gate before adding a restricted salvage upgrade.

**Daily:** continue giving exactly one predetermined legal choice. A new local fork is selected by the Daily seed, not an extra player menu. Bump the Daily ruleset when gameplay or offer generation changes, and reconstruct the full predetermined sequence through the new resolver.

**Existing progress:** do not silently drop a player's run, collection or purchased upgrade. The only proposed new conflict between existing IDs is Rail spike + Vector. Before enabling that exclusion, version saved build legality and allow that legacy combination to finish its existing run with its previous behavior. Preserve historical builds and mark them as legacy where necessary; new Workshop builds and rewards use the new rules. Never accept a forged “legacy” marker without the corresponding validated old save format. Existing Burst + Thermal builds stay legal.

**Presentation:** one or two short card sentences describe the gun the player will actually get. Show a compact local specialization label only where useful. Offer a discovered-build interaction explanation in Workshop details, not persistent combat text, and do not expose future enemies or undiscovered upgrades.

### Delivery sequence

1. **Compatibility release:** Rail adapters/exclusion, Breach budget, contextual descriptions and versioned save handling. Prove the current build rules before changing reward variety.
2. **Flight cleanup:** Recall/Mass Driver leg accounting, guided Recall timing, and echo guidance/saw inheritance. Keep these changes separate enough to compare boss damage and dense builds.
3. **First new branch release:** Pulse Chamber, Charge Lens and Prism Array. Build the local-choice resolver once and use the beam to validate it end to end.
4. **Second branch release:** Pinwheel, Follow-through, Shaped Charge and Cluster Shell. Check room-clear speed and area coverage against the beam branches.
5. **Shared and salvage branches:** Skid Plate, Relay Gate, Short Circuit, Triphammer and Crosscut. Add these after the first seven new cards have survived playtesting.

### Acceptance scenarios

- Extend the generated inventory to include new definitions, inherited exclusions and both acquisition orders. An allowed pair must have a named runtime expectation, not just pass `availableMods`.
- Test **Ray + Scattershot + Burst + Thermal + each specialization**, then add one of Banker, Backfire, Capacitor, Splinter, Arc Coil, Tether or Countershot. Compare 30/60/120 Hz damage, recoil, charge spending and visible gaps.
- Test **Rail + Scattershot + Backfire + Grindshot + Capacitor**, including wall-first, enemy-first, piercing, banked, fully blocked and expired shots. Test the Vector exclusion, old Continue and old recap handling separately.
- Test **Mass Driver + Recall + Homecoming + Banker + portals**, then Drop Forge or Skid Plate. Count per-enemy hits across both legs and verify that a portal or bounce cannot renew the allowance.
- Test **Crossfire + Scattershot + Afterimage + Vector + Afterburner + Grindshot**, with Parallax or Follow-through. Check recorded direction, cover at release, finite descendants and total effect counts.
- Test **Shellshock + Fuse + Linked fuse + Aftershock + Shockfront + Tripwire** with each allowed shell specialization. Verify shape, host rotation, actual cover, finite chains and bounded blast-surf movement.
- Test **Breach + Countershot + Hair trigger + Burst + Backfire** against sustained boss pressure. Standing still and holding fire must leave dangerous attacks; intentional movement and timing must still receive the upgrades' benefits.
- Test force-heavy builds against trains, lifts, crates, rotated geometry and portals. No physical projectile/secondary may arrest moving machinery or force a body through solid cover.
- For every new branch: pause, hitstop, room change, death, fresh-seed retry, Continue, Daily reconstruction, Workshop add/remove, controller release and lost focus. Temporary charges, links and pending discharges stay room-local.
- Compare equal-depth builds across groups, lone armored bosses and moving targets. Measure sustained damage, burst damage, time-to-kill, hit coverage and movement utility. A branch may trade one for another; it must not win all five by default.
