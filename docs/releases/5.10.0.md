# Loading & performance — 5.10.0

Workshop, Logbook documents and pictures, room rematches, support drills and replay viewing now load when opened. Upgrade cards remain usable while their optional gun comparison loads. Slow or failed tool downloads offer Back and Retry; late downloads cannot reopen a closed menu or revive disposed practice scenes. The title counts unread entries without building the full Logbook catalog.

Actual game photographs fill in only as they enter view, one per task. The retained thumbnail cache holds at most twelve 640×320 canvases (9.4 MiB of RGBA backing pixels), releasing older backing canvases as you browse. Closing or replacing a menu cancels queued photography. Images still use the production game and renderer.

Projectile sweeps reject distant cover before projecting its convex vertices, and avoid temporary projection arrays. Live Matter bounds keep moving and rotating cover current. Replay capture requests a bitmap at replay resolution before transferring it to the encoder; the existing worker, letterboxing, final death frame, queue limits and fallback remain. A 3840×2160 source now transfers at most 854×480 pixels, about 95% fewer pixels; that is a transfer-size bound, not a measurement of total browser memory. Ammo lighting, damage, shot counts and collision outcomes retain their existing rules.

## Measured comparison

Two paired native CPU runs per version, each with five 600-tick rounds per scenario. The first 120 ticks per round are warm-up; each version contributes 4,800 measured ticks per scenario. These are **simulation CPU timings**, not browser FPS. Same Windows machine, Node 24, ordinary deterministic input, no competing test suite and no artificial CPU throttling. OS activity and thermal variation remain uncontrolled.

| Measurement                      |           5.9.0 |          5.10.0 |
| -------------------------------- | --------------: | --------------: |
| Heavy beam simulation, mean      |   1.375 ms/tick |   0.940 ms/tick |
| Chain explosion simulation, mean |   0.763 ms/tick |   0.496 ms/tick |
| Heat + mortar simulation, mean   |   0.116 ms/tick |   0.116 ms/tick |
| Eager game JavaScript, raw       | 1,461,945 bytes | 1,340,152 bytes |
| Eager game JavaScript, gzip      |   477,155 bytes |   435,349 bytes |

That is about 32% less simulation work in the beam preset, 35% less in explosions, and 9% less compressed startup JavaScript. Native rendering remained approximately unchanged (beam means 2.01 → 2.07 ms); no renderer FPS gain is claimed. Isolated V8 compilation varied substantially between runs and showed no consistent improvement. A cached-glow experiment made CPU rendering slower and was excluded from the final game.

The simulation soak covered six equivalent input minutes and sixty actual combat deaths. A separate rematch audit opened 120 sessions and reset them 480 times: fresh physics counts stayed bounded, every disposed world had zero bodies/pairs, the original result stayed unchanged and no checkpoints were written. Heap samples describe Node JS memory after explicit GC; they do not measure browser canvases, GPU allocations or every possible leak.

[Raw measurements, paired runs and methodology](../performance/5.10.0.json). The embedded browser previously delivered about one frame per second despite short callbacks; those samples cannot establish normal hardware FPS. No slow frames have been discarded or reclassified as a successful hardware test.

## Validation and reproduction

All 3,084 regular regression tests plus the new archive-loading lifecycle test passed locally. New coverage checks exact sweeps against the pre-optimization SAT reference, notification parity across 300 progression states, lazy-download retry/cancellation, cache eviction, visible-only queued photography, large/portrait/ultrawide replay snapshots and unsupported-resize fallback. The four regular and eight maximal-build CI shards remain intact.

Build with `npm run build`. For the optional historical loading reference, run `python scripts/stage-loading-reference.py`; Pages CI stages it after the game build. The script verifies the immutable 5.9.0 release archive's SHA-256 and copies only HTML, icon and JS/CSS assets into diagnostic-only directories. The normal game never requests them. For an offline copy, pass `--archive path/to/recoil-foundry-v5.9.0-site.zip`. An ordinary local/release build without this fixture still measures its current title and clearly reports the missing comparison.

Run `node --experimental-vm-modules scripts/loading-audit.mjs dist output.json` for eager module sizes and isolated V8 compile samples. Run `node --expose-gc --experimental-strip-types scripts/rematch-soak.ts output.json` for repeated lifecycle checks. `scripts/render-performance.ts output.json [source-root]` uses the optional existing `@napi-rs/canvas` installation; set `RF_CANVAS_PACKAGE` to its package-resolution root when installed elsewhere. It is separate from the required test suite and browser GPU testing.
